# /lhg-earnings:earnings —— 财报解读主流程

用户输入在 `$ARGUMENTS` 中：财报原文（直接粘贴）、或财报文本/数据文件路径。

全程按 skill `lhg-earnings-flow` 执行，指标口径查 `lhg-earnings-indicators`，
风险清单按 `lhg-earnings-risks` 逐项扫描，输出前按 `lhg-earnings-compliance` 自查。

## 流程

### 1. 数据结构化

- 确认：公司全称、报告期、单位（全文统一）、数据来源
- 拆成利润表 / 资产负债表 / 现金流量表三清单，缺的项标「缺数据」
- **铁律**：数字只抄不算，不许脑补缺失数据

### 2. 建 data.json 并跑审计脚本

把结构化数据写成 `data.json`（字段见 `scripts/audit/earnings_audit.py` 顶部注释），然后：

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/earnings_audit.py --target <数据目录> --format text
```

- 公式复算偏差 > 1 个百分点 → 先对账，不许带着偏差往下解读
- blocker（现金流背离等）→ 必须进风险清单首位

### 3. 趋势解读

- 同比（vs 上年同期）+ 环比（vs 上一期），数字先行
- |营收增速| > 50% / 利润剧烈波动 → 先排除并购、剥离、非经常性损益
- 主业成色看扣非净利润增速

### 4. 风险清单

按 `lhg-earnings-risks` 十大风险逐项扫描，每条写三段式：
**现象**（数字）→ **可能的原因**（2-3 种）→ **待验证**（去哪找证据）。

### 5. 写报告（固定结构）

```
# XX公司 XXXX年财报解读

数据来源：……；单位：……

## 核心指标（表格）

## 趋势解读

## 风险清单

---

**合规声明**：数据源短板——本解读依赖用户提供或公开数据快照，
非实时行情；本插件仅做财务数据解读教育，不构成投资建议。
```

### 6. 输出前合规自查（必做）

1. 全文无"买入/卖出/目标价"等投顾表述
2. 末尾有完整合规声明
3. 每个数字可追溯到输入，无编造
4. 审计脚本 blocker 清零

## 硬规则

- 输出买卖建议 → 不许，这是红线。
- 缺数据时编数字凑报告 → 不许，写「缺数据」。
- 跳过合规自查直接发报告 → 不许。
