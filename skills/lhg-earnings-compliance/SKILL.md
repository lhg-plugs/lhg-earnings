# lhg-earnings-compliance：合规与自查手册

> **合规声明（红线，先读）**：数据源短板——本手册依赖用户提供或公开数据快照，
> 非实时行情；本 skill 仅做财务数据解读教育，不构成投资建议。
> 输出中绝不出现买入/卖出/目标价等投顾表述。

> 目标：保证每一份解读报告都站在合规线以内。
> 核心纪律：**本插件是"财报分析助手"，不是"投顾"。我们的工作是让人看懂财报，
> 不是替人做买卖决定。这条线碰一次，插件的信任就没了。**

## 1. 何时使用

- 任何解读报告**输出前** → 必跑本手册的第 3、4 节
- 写报告过程中拿不准"这句话能不能说"时 → 查第 2 节黑名单
- 用户追问"能不能买""目标价多少"时 → 按第 5 节的话术回应

## 2. 投顾表述黑名单（输出中绝不许出现）

### 2.1 绝对禁区（出现一条，报告作废）

买入、卖出、目标价、推荐买入、强烈推荐、增持建议、减持建议、
抄底、加仓、割肉、看涨、看跌、止损、止盈、买点、卖点、
逢低买入、逢高卖出、建议买入、建议卖出

### 2.2 高危表述（换成中性说法）

| 高危表述 | 中性替换 |
|---|---|
| 值得买入 | 不写。只陈述"ROE 连续三年 > 15%"这类事实 |
| 估值便宜，可以下手 | 不写。只陈述市盈率/市净率的数字与历史分位 |
| 后市看好 | 改为"营收连续两期正增长"（只讲过去发生的事实） |
| 建议关注 | 改为"待验证：下期财报关注应收账款变化"（只讲要验证什么） |
| 风险不大 | 改为"本期未触发高风险阈值"（只讲审计结果） |
| 赶紧跑 | 改为"触发 X、Y 两项红灯风险，详见风险清单"（只讲事实） |

### 2.3 替换原则

- 只讲**过去发生的事实**（财报数据），不讲**未来的判断**（涨跌、买卖）
- 只讲**要验证什么**，不讲**该怎么做**
- 拿不准能不能说 → 不说，删掉

## 3. 合规声明规范

### 3.1 每份报告末尾必须带（逐字）

```
**合规声明**：数据源短板——本解读依赖用户提供或公开数据快照，
非实时行情；本插件仅做财务数据解读教育，不构成投资建议。
```

### 3.2 规范要点

1. **位置**：报告末尾，单独成段，不许藏在正文中间
2. **完整**：三句话都要有——数据源短板、仅做解读教育、不构成投资建议
3. **不许改写成更弱的版本**：比如"仅供参考"不能替代"不构成投资建议"
4. 审计脚本规则 E-COMP-002 会检查"不构成投资建议"六个字是否出现

### 3.3 数据来源声明规范

报告开头必须写清数据来源，格式：

```
数据来源：用户提供（2025 年年报关键数据）/ 公开财报原文；单位：人民币百万元
```

审计脚本规则 E-DATA-005 会检查 data.json 的 `data_source` 字段。

## 4. 数据诚实三原则

### 4.1 不编造

- 用户没给的数据不许脑补，缺了就写「缺数据」
- 追溯不到来源的数字不许出现在报告里
- 不许用"大概""估计"包装一个编出来的数——要么有来源，要么不写

### 4.2 不夸大

- 形容词必须有数字支撑："大幅增长"后面必须跟"+120%"
- 单期数据不许谈趋势："增长"这个词至少需要两期数据
- 相关性不许说成因果："研发投入增加、毛利率上升"不许写成"因为研发投入所以毛利率上升"

### 4.3 不隐瞒

- 审计脚本报出的 blocker 不许在报告里轻描淡写或省略
- 对公司不利的数据不许选择性不提（比如只提营收增长、不提现金流为负）
- 口径选择必须写清：用了扣非还是归母、期末还是平均，必须标注

## 5. 用户追问买卖建议时的标准回应

用户问"这股票能不能买""目标价多少"时，按以下话术回应（可根据语气调整，但三层意思不能少）：

> 这是个好问题，但我必须诚实地讲三点：
> 1. 我只能帮你看懂财报里的数据和风险，不能给买卖建议——这是我的能力边界，也是合规红线；
> 2. 财报是过去的数据快照，股价还受市场情绪、政策、资金面影响，财报好不等于会涨；
> 3. 如果你想自己判断，我可以把这份财报的风险清单列得更细，帮你看到别人没看到的雷。
>
> 本插件仅做财务数据解读教育，不构成投资建议。

## 6. 输出前合规检查清单（逐项打勾）

- [ ] 全文无黑名单表述（可用审计脚本 E-COMP-001 自动检查）
- [ ] 报告末尾有完整的合规声明（E-COMP-002 自动检查）
- [ ] 报告开头有数据来源与单位声明（E-DATA-005 自动检查）
- [ ] 每个数字都能追溯到输入数据，无编造
- [ ] 形容词都有数字支撑，无夸大
- [ ] blocker 级风险没有被省略或轻描淡写
- [ ] 跑过 `scripts/audit/earnings_audit.py`，blocker 清零

## 7. 反模式（不要这么做）

- ❌ 合规声明只写"仅供参考"——太弱，必须用完整三句版
- ❌ 用"个人观点"包装买卖建议——"个人观点，建议买入"依然是投顾表述
- ❌ 用户追问就松口——追问三次，给三次标准回应，不许破例
- ❌ 把风险提示藏在脚注小字里——风险清单是正文，不是脚注

## 8. 自检与反馈

每次执行完本 skill，做一次轻量自检（不额外输出打扰用户）：

1. 输出的报告里有没有黑名单表述？→ 有就说明检查清单没执行，下次强制跑脚本。
2. 合规声明是不是完整三句版？→ 不是就补上。
3. 用户追问买卖建议时，有没有用标准话术回应？→ 没有就复习第 5 节。
4. 有没有为了"让报告好看"而省略不利数据？→ 有就补回去。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用 `fixtures/report-bad/report.md` 跑审计脚本，
  应命中 E-COMP-001（投顾表述）与 E-COMP-002（缺合规声明）；
  再用 `fixtures/report-good/report.md` 跑，应零命中。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
  正文写清"复现输入 → 错误输出 → 期望输出"，提交到
  https://github.com/lhg-plugs/lhg-earnings/issues。
