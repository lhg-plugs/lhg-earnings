# lhg-earnings-flow：财报解读主流程

> **合规声明（红线，先读）**：数据源短板——本流程依赖用户提供或公开数据快照，
> 非实时行情；本 skill 仅做财务数据解读教育，不构成投资建议。
> 输出中绝不出现买入/卖出/目标价等投顾表述。

> 目标：把一份财报（年报/季报文本或关键数据），变成一份"看得懂、用得上"的解读报告。
> 核心纪律：**先结构化数据，再算指标，最后才解读。顺序错了，解读全是编的。**

## 1. 何时使用

- 用户粘贴了一份财报全文或关键数据，说"帮我看看"时 → 跑完整流程
- 用户只想快速知道"这家公司赚不赚钱"时 → 只跑第 3 步（指标速览）
- 用户已经有历史数据、想看变化时 → 重点跑第 4 步（趋势对比）
- 输出前 → 必跑第 6 步（合规自查）

## 2. 输入与输出

- **输入**：财报原文（年报/季报 PDF 转文本）、或用户粘贴的关键数据（营收、利润、资产等）
- **输出**：一份解读报告，结构固定为：数据快照 → 核心指标 → 趋势对比 → 风险清单 → 合规声明

## 3. 第一步：数据结构化（地基）

### 3.1 先回答四个问题

1. **这是谁的财报？**——公司全称、报告期（2025 年年报 / 2025Q3 季报）
2. **单位是什么？**——万元 / 亿元 / 百万元，全文必须统一，不许混用
3. **数据从哪来？**——用户粘贴 / 公开财报原文，写进报告的"数据来源"栏
4. **缺什么？**——三张表齐不齐？缺现金流量表就写"缺现金流量表，现金流相关结论不做"

### 3.2 结构化成数据表

把财报拆成三个清单，缺的项明确标注「缺数据」：

- **利润表项**：营收、营业成本、毛利、费用（销售/管理/研发/财务）、营业利润、净利润、扣非净利润
- **资产负债表项**：总资产、总负债、净资产、货币资金、应收账款、存货、商誉、有息负债
- **现金流量表项**：经营现金流、投资现金流、筹资现金流

### 3.3 铁律

- 数字只抄、不算：这一步不许做任何计算，计算是第 4 步的事
- 单位换算写清楚：比如"财报原文为亿元，此处统一换算为百万元"
- 用户没给的数据不许脑补：缺了就写「缺数据」，解读时跳过对应结论

## 4. 第二步：核心指标计算

### 4.1 计算前先确认口径

每个指标算之前，先问自己"分子分母用的是什么"：

- 净利率用"归母净利润"还是"扣非净利润"？→ 优先扣非，看主业成色
- ROE 用"期末净资产"还是"平均净资产"？→ 简易解读用期末，写清口径
- 季报数据要不要年化？→ 不年化，直接标注"单季数据，未年化"

### 4.2 必算的 8 个指标

| 维度 | 指标 | 公式 |
|---|---|---|
| 盈利 | 毛利率 | （营收 - 营业成本）/ 营收 |
| 盈利 | 净利率 | 净利润 / 营收 |
| 盈利 | ROE | 净利润 / 净资产 |
| 杠杆 | 资产负债率 | 总负债 / 总资产 |
| 现金流 | 经营现金流 | 直接取数，不计算 |
| 现金流 | 现金流利润比 | 经营现金流 / 净利润 |
| 质量 | 应收账款增速 | 本期 vs 上年同期 |
| 质量 | 存货增速 | 本期 vs 上年同期 |

详细公式与口径陷阱见 skill `lhg-earnings-indicators`。

### 4.3 计算纪律

- 用确定性脚本算（本插件 `scripts/audit/earnings_audit.py` 会复算），不许心算
- 公式复算偏差超过 1 个百分点 → 先对账，不许带着偏差往下解读
- 算不出来的指标 → 写「缺数据」，不许估一个数填上

## 5. 第三步：趋势对比（多期）

### 5.1 对比什么

- **同比**：本期 vs 上年同期（消除季节性），看"变好了还是变坏了"
- **环比**：本期 vs 上一期（季报场景），看" momentum 是加速还是减速"
- **结构**：本期各费用占营收的比例 vs 历史，看"钱花在哪了"

### 5.2 解读三问

每看到一个变化，连续问三个问题：

1. **变化有多大？**——先报数字："营收同比 -20%，从 1000 降到 800"
2. **是一次性的吗？**——并购/剥离/会计政策变更/非经常性损益，先排除再谈趋势
3. **主业变了吗？**——扣非净利润的增速，才是主业的真实体温

### 5.3 反模式

- ❌ 拿单期数据谈"趋势"——一期只能叫快照，两期以上才叫趋势
- ❌ 把并表增长当内生增长——先问"增长里有没有并购贡献"
- ❌ 只看净利润不看扣非——非经常性损益能把亏损做成盈利

## 6. 第四步：风险清单

风险清单是解读报告的"干货区"，按 skill `lhg-earnings-risks` 的清单逐项过：

1. **现金流背离**：净利为正、经营现金流为负 → 放首位
2. **高杠杆**：资产负债率 > 70%
3. **商誉**：商誉 / 净资产 > 30%
4. **应收暴涨**：应收增速 - 营收增速 > 20 个百分点
5. **存货积压**：存货增速 - 营收增速 > 20 个百分点
6. **毛利率塌方**：同比下滑 > 5 个百分点
7. **现金流失血**：经营现金流为负

每条风险写三段式：**现象**（数字）→ **可能的原因**（2-3 种，不许只给一种）→ **要去验证什么**（去财报附注/公告里找什么）。

## 7. 第五步：写报告

### 7.1 固定结构

```
# XX公司 XXXX年财报解读

数据来源：……（用户提供/公开财报原文）；单位：……
报告期：……

## 核心指标（表格）

## 趋势解读（同比/环比，数字先行）

## 风险清单（现象→可能原因→待验证）

---

**合规声明**：数据源短板——本解读依赖用户提供或公开数据快照，
非实时行情；本插件仅做财务数据解读教育，不构成投资建议。
```

### 7.2 写作纪律

- 每个结论后面跟数字，不许出现"大幅""显著"这种没有数字的形容词
- 不确定的写"待验证"，不许写"大概率"
- 风险清单不许轻描淡写：现金流背离这种红灯必须放首位
- 报告末尾必须带合规声明，一字不许少

## 8. 第六步：合规自查（输出前必做）

1. 全文搜索投顾表述（买入/卖出/目标价/抄底/加仓/看涨/止损……）→ 有一条就删一条
2. 确认末尾有"不构成投资建议"声明 → 没有就补上
3. 确认没有编造数据：每个数字都能追溯到输入 → 追溯不到的删掉
4. 跑一遍 `scripts/audit/earnings_audit.py` → blocker 清零才能发

## 9. 反模式（不要这么做）

- ❌ 用户只给了营收和净利润，就敢写"全面解读"——缺数据就承认缺
- ❌ 用"管理层很优秀""赛道很好"这种无法验证的话凑字数
- ❌ 把"风险提示"写成走过场的一句话——风险清单是报告最有价值的部分
- ❌ 输出买卖建议——这是红线，碰一次插件就废了

## 10. 自检与反馈

每次执行完本 skill，做一次轻量自检（不额外输出打扰用户）：

1. 数据结构化时有没有脑补缺失数字？→ 有就删掉，下次先标「缺数据」。
2. 指标计算有没有心算？→ 下次走脚本复算。
3. 风险清单有没有把现金流背离放首位？→ 没有就调整顺序。
4. 输出里有没有出现投顾表述？→ 有就说明流程第 6 步没执行，下次强制执行。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用 `fixtures/report-good/` 的数据走一遍本 skill，
  检查是否输出了固定结构的报告、风险清单是否完整、末尾是否有合规声明。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
  正文写清"复现输入 → 错误输出 → 期望输出"，提交到
  https://github.com/lhg-plugs/lhg-earnings/issues。
